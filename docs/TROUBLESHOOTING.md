# 故障排查

**语言 / Language:** 中文 · [English](/en/TROUBLESHOOTING.md)

桌面端的原则是**不白屏、不静默失败**：后端起不来就弹管理面板，出问题就留下日志。下面按"先取证、再对症"的顺序写。

## 第一步：收集诊断

菜单栏 → **收集诊断 / Collect diagnostics**。它会把下面这些打包到 `<日志目录>/diagnostics-<UTC 时间戳>/`，并在文件管理器里打开：

| 内容 | 说明 |
| :-- | :-- |
| 主日志 + 轮转文件 | 启动、发现运行时、后端 stdout/stderr、前端转发的错误 |
| `last-run.json` | 上次运行是正常退出还是崩溃 |
| `crash-*.ips` | macOS 原生崩溃报告（上次运行不干净时自动从系统目录复制，系统会清理原件） |
| `doctor.json` | 后端自检输出 |
| `config.json` | 你当前配置，**疑似机密的字段会被替换成 `"***"`** |
| `env.txt` | 平台、版本等运行环境信息 |

想自己看日志：菜单栏 → **Open logs**。

## 应用起不来、窗口一直没内容

窗口底部会显示后端状态（端口 / PID / 健康状态）。按状态对症：

| 现象 | 常见原因 | 处理 |
| :-- | :-- | :-- |
| 管理面板弹出，提示运行时找不到 | 源码运行却没拉真实运行时 | 跑 `npm run runtime:fetch`；打包版正常不会有这条 |
| 状态一直"启动中"然后失败 | 端口被别的程序占用 | 见下一节 |
| 后端进程秒退 | 随包 `node` 缺失、被杀软拦截、权限问题 | 看日志里后端的 stderr；把诊断包发出来 |
| 窗口空白、无状态行 | 主窗口没拿到内容 | 先看日志里有没有前端错误（前端错误会转发到 Rust 侧日志） |

运行时发现顺序是 **bundle → config → PATH → mock**：日志里能看到最终用了哪一个（`bundled` / `config` / `path` / `mock`）。开发时的 `mock` 就是仓库里提交的轻量替身，不是真实 PixivFlow。

## 端口被占用

默认端口是 **3000**（`desktop-config.json` 里的 `backend.port`）。

- 如果占用端口的进程**是上一次崩溃留下的 PixivFlow 后端**，桌面端会**接管**它（不会起第二个）——状态里会显示为已接管的进程。接管只在监听进程的命令行里包含 `pixivflow` 时发生，避免误接管别人的服务。
- 如果是**其他程序**占着端口，桌面端不会去杀它。两个办法：把那个程序挪走，或改端口：

```jsonc
// <应用数据目录>/desktop-config.json
{
  "mode": "local",
  "backend": { "port": 3100, "autoStart": true }
}
```

改完重启应用。`backend.command` / `backend.args` 可以覆盖后端启动命令（默认用 bundle 里的运行时）。

## 界面白屏或样式全丢

桌面端不自己渲染前端：它启动本地后端，后端用 `STATIC_PATH` 把 WebUI 发出来，窗口加载的就是这个地址。所以：

- **后端没起来** → 应该看到管理面板而不是白屏。真白屏请收集诊断，看日志里有没有后端退出记录。
- **后端起来了但页面空** → 多半是 WebUI 产物不在。打包版自带；**源码运行**需要 `npm run webui:fetch` 合成真实 WebUI，否则用的是占位页。
- 前端抛错会通过 host bridge 转发到 Rust 日志（`log_frontend`），诊断包里能看到。

## 登录相关

- **授权页没弹出**：用菜单栏的 *Cancel sign-in* 收掉，再重试一次。授权页是应用内**浮层**，不开外部浏览器。
- **授权完成却没回到 PixivFlow**：确认没有在浮层里误关窗口；重试登录即可。反复失败时，先用命令行跑一遍上游的登录流程，确认是账号/网络问题还是桌面端问题。
- **需要代理**：桌面端不接管网络设置，代理请在 PixivFlow 自己的配置里设置。
- 凭据只落在你自己的数据目录，桌面端不转发、不上传。

## 数据会不会丢

不会。你的 PixivFlow 数据在**每用户应用数据目录**（`config/`、`data/`、`downloads/`），不在应用安装目录里，所以升级、重装、换安装包都不会动它。桌面端自己的配置是同一层目录下的 `desktop-config.json`。想备份就整目录备份。

## 反馈问题时请附上

1. 诊断目录（压缩后）——里面已经包含日志、`last-run.json`、崩溃报告、`doctor.json` 和脱敏配置；
2. 系统版本与桌面端版本（菜单栏/关于，或 `PixivFlow-Desktop-v<版本>-*` 文件名）；
3. 复现步骤：点了什么、期望什么、实际什么。

有这三样基本不用再来回一轮。仍未解决的话，带上诊断包到 [Issues](https://github.com/redtidev1918/pixivflow-desktop/issues) 提一个。
